# 验收标准

- Status: confirmed
- Prerequisites: [01-background-and-goal.md](./01-background-and-goal.md)
- Evidence: G-01 至 G-06、C-01 至 C-06、已确认原型
- Confirmed decisions: D-01 至 D-19
- Blocking open questions: 无

## 文档预览与 Diff

### AC-01 插件侧分类

- 分类发生在插件收到实际 ACP 写入审批请求之后，不依赖或修改 Agent 的 Plan 生命周期。
- 目标文件不存在时进入“新增文件预览”。
- 已有文件未打开时，实际变化达到 `18` 行、`1600` 字符任一阈值才进入完整 Review；ACP 传递完整旧文和新文本身不升级 Review。
- 其余修改进入局部 Diff。
- 阈值只决定审阅 UI，不改变 Agent 行为、ACP Permission 选项或写入内容。

### AC-02 新增文件预览

- 新增文件不展示红绿 Diff。
- 插件在文档 Editor 区打开只读临时文档，完整显示待创建内容；确认前文件系统中不得出现目标文件。
- 用户选择 Yes 后，插件把允许结果返回 Agent，不自行代写文件。
- Agent 实际创建的内容与批准候选一致后，临时文档关闭并打开真实文件。
- 用户选择 No 或提交替代意见时，临时文档关闭，目标文件不得被创建。

### AC-03 局部修改审阅

- 目标文档已打开时，无论变化大小，都在原文档中临时插入候选内容并直接呈现 Diff，自动将视区定位到第一处实际修改。
- 原文档内联预览只使用整行红色删除、整行绿色新增；确认操作仍保留在 Agent 确认区域。
- Yes、No、自由意见或请求失效前，插件必须先移除临时插入内容；如果 Auto Save 已保存临时内容，必须先把审批前原文恢复到磁盘。
- 目标文档未打开时，在现有确认区域展示只覆盖当前修改的紧凑 Diff。
- 同一修改不得同时在 Editor 和确认区域重复展示两份 Diff。
- 确认前原文不得发生正式写入。

### AC-04 Diff 视觉

- 仅实际发生变化的行显示语义高亮。
- 删除行整行红色，增加行整行绿色，不使用删除线。
- 未变化上下文保持普通背景和普通文字色。
- `Changes` 按最终文档顺序展示上下文、删除行和新增行。

## 完整候选稿 Review

### AC-05 自动拉起 Review Editor

- 只有目标文档未打开且命中完整 Review 条件后，才在 Hermes Agent Editor 右侧自动创建独立临时 Review Editor。
- Review Editor 不与 Hermes Agent Tab、普通文档 Tab 混放。
- 顶部状态明确显示：`候选修改已完成 · 尚未应用到原文`。
- 原文在用户允许前保持不变。

### AC-06 Result 与 Changes

- Review 默认打开 `Result`，完整展示候选文档。
- `Changes` 展示候选文档相对原文的单栏 Unified Diff。
- Result 与 Changes 在同一 Review Editor 内切换，不改变 Pending 状态。
- Result 和 Changes 均允许滚动、选择和复制，窄宽下不得造成会话区横向溢出。

### AC-07 最终决定

- Review 自动打开时，Agent 会话同时保留原 ACP 确认选项。
- 用户选择允许后，由 Agent 执行原写入；插件不得绕过 ACP 自行覆盖文件。
- 用户拒绝后关闭 Review，原文保持不变。
- 原文在审阅期间发生变化时，禁止继续允许当前候选，提示重新生成。

### AC-08 替代意见与复用

- 用户提交替代意见时，当前候选稿先按拒绝处理，原文保持不变。
- 意见直接注入当前 ACP 轮次，不经过 Queue，不产生可见 Steer 消息，也不创建新的 Assistant continuation。
- 当前 Working 记录审批问题和用户最终输入，后续 Thinking/Action 继续追加在同一 Working 中。
- 同一会话、同一目标路径产生下一版候选时，复用原 Review Editor，并在生成期间显示等待状态。
- 新候选到达后同一 Review Editor 更新为新的 Result/Changes，不创建多个审阅区域。

### AC-09 临时 Editor 生命周期

- Pending 时手动关闭新增文件预览或 Review Editor，请求保持 Pending。
- 现有确认区域提供重新打开预览/审阅的入口，系统不反复强制拉起。
- 正常允许、拒绝、会话关闭或请求失效后，清理虚拟文档、装饰和 Review Editor。

### AC-10 写入边界

- 插件只提供预览、冲突校验和 Permission 响应，不直接执行 Agent 原本申请的文件写入。
- 允许前使用审批时的原文快照校验目标文件；内容已更新时阻止迟到允许。
- 新增文件只在 Agent 完成真实创建后切换到真实文件 Tab。

## 通用确认组件

### AC-11 复用现有框架

- 新组件必须渲染在当前 `.permission-panel` 的既有位置。
- 不改变确认区域相对输入框、队列、Todo 和会话内容的层级关系。
- 不创建新的 Modal、浮层定位系统或独立卡片风格。
- 使用当前主题 token，适配浅色、深色和高对比度主题。

### AC-12 直接提交

- 点击任意预设选项立即提交。
- 自由输入框按 `Enter` 立即提交。
- `Shift+Enter` 只插入换行，不提交。
- 输入法组合输入期间按 Enter 不得误提交。
- 空输入按 Enter 不产生请求。
- 不显示“继续”“确认选择”或其他二次提交操作行。

### AC-13 输入互斥与防重复

- 选择预设选项时清空自由输入。
- 用户开始输入文字时取消已选择的预设项。
- 提交开始后立即禁用全部选项和输入框。
- 同一个 `requestId` 只能产生一次有效响应。
- 渲染刷新、连续点击和 Enter 连按不得产生重复请求。

### AC-14 场景语义

| 场景 | 预设选择 | 自由输入 |
| --- | --- | --- |
| Edit | 应用或放弃当前 Diff | 取消当前 Diff，原文不变，按意见重新生成 |
| Execute | 执行或拒绝当前动作 | 不执行当前动作，按意见重新规划 |
| Review | 应用或放弃候选稿 | 不应用候选稿，按意见更新后重新审阅 |
| Clarify | 返回预设答案 | 直接返回自定义答案 |

- 自由输入在任何情况下都不得隐式映射为 Allow。
- 不支持自由意见的系统级安全输入继续使用原有专用组件。

### AC-15 Pending 与归属

- 确认请求无限等待用户主动选择或输入。
- 可选提醒不得调用响应接口，也不得关闭确认区域。
- 请求必须绑定创建它的 `sessionId + requestId`。
- 会话终止、传输断开或请求失效时，清理 UI 和临时预览，不发送迟到响应。

## Working 过程

### AC-16 本地文档动作

- Read、Edit、Write 等动作后的可见文字只展示文档名称。
- tooltip 展示完整路径。
- 默认文字使用普通正文颜色，不使用蓝色或分段高亮。
- hover 时完整文档名称出现一条连续下划线。
- 点击后在文档 Editor 区打开；支持 VS Code 已安装编辑器可处理的文档类型。

### AC-17 外部网址动作

- 完整 URL 被识别为单一链接，不拆成多个路径片段。
- 默认使用普通正文颜色。
- hover 时整段 URL 出现连续下划线。
- 点击通过 VS Code 外部打开能力调用系统浏览器。

### AC-18 代码执行动作

- Python、Shell、JavaScript 等代码执行类 Action 的标题行不得直接展示代码、命令正文或被截断的代码片段。
- 标题格式为“动作类型 + 自然语言简述”，例如 `Run Python 解析配置并生成候选文档`。
- 自然语言简述应说明动作目的，不复述实现细节；无法获得可靠简述时，只显示规范化动作名称，不猜测用途。
- 原始脚本或命令放入该 Action 既有的可展开详情区，折叠状态不占用标题行。
- 执行结果仅在对理解或诊断有价值时放入展开详情区；空结果不创建占位内容。
- 只有同时存在明确输入与输出，或两者的区分能显著帮助审阅时，才使用 `IN/OUT` 表格。
- 仅有脚本时使用单一代码块；仅有结果时使用单一结果块；不得为统一形式而制造空 `IN` 或空 `OUT`。
- 代码详情继续复用现有展开容器、代码字体、滚动和主题样式，不新增独立卡片或时间线层级。

### AC-19 任务中问答记录

- Agent 在执行过程中提出的问题显示在对应 Working 时间线位置。
- 用户选择或自由输入的最终回答与问题成组显示。
- Agent 继续执行后，问答记录不得被流式更新覆盖或移到 Response。
- 会话恢复后仍保留问题和回答。

## 回归保护

## Run Settings Model

### AC-20 Model 布局

- Run Settings 顶部不显示 Reset 按钮。
- Mode 区块的选项、说明、选择语义和持久化保持不变。
- Mode 下方显示 `Model` 标题。
- Model 下拉框位于标题下一行并占满可用宽度，不采用 label/value 左右布局。
- 下拉框沿用现有 Popover、字体、边框、圆角、主题变量和窄宽适配规则。

### AC-21 Model 数据与切换

- 已建立 ACP 会话时，选项使用该会话返回的 `availableModels`，当前值使用 `currentModelId`。
- ACP 会话尚未建立时，选项使用 Hermes 当前 provider 的本地配置模型；当前默认模型必须可见。
- 插件不得使用 `package.json` 中的静态默认值伪造可用模型列表。
- 用户选择模型后，当前 UI 会话立即保存该模型；若 ACP 会话已建立，调用 `session/set_model`。
- 切换失败时恢复原选择并显示明确错误，不保存失败值。

### AC-22 Model 继承与失效回退

- 每次成功选择模型后保存为全局“上次选择模型”。
- 新会话创建时继承该值，并在首次建立 ACP 会话后应用。
- 若继承值不在当前真实可用模型列表中，回退到 Hermes 当前默认模型或 ACP 返回的当前模型。
- 已存在会话继续保留各自保存的模型，不因其他会话切换而被覆盖。

### AC-23 已修功能不得回退

实施后必须验证以下既有能力保持不变：

- 会话区域随最小 Editor 宽度自适应。
- 多附件保持单行并在附件行内部横向滚动。
- 长用户消息可展开，并在展开后保持状态。
- Agent 流式输出不抢走输入框焦点。
- Queue 编辑保持原顺序，Steer 不重复发送。
- Todo 胶囊位置、展开收起和进行中动效不变。
- 运行中 Thinking 单步约 10 行，结束后完整展开。
- Stop、Interrupted、历史搜索和标题编辑不回退。

## 必需验证证据

- 单元/契约测试覆盖状态和消息归属。
- Webview 真实浏览器测试覆盖直接点击、Enter、Shift+Enter、输入法组合、防重复提交。
- VS Code Extension Host 测试覆盖文档已打开/未打开、临时 Editor 创建与关闭、Apply/Deny/反馈重生成、ACP Model 列表和切换失败回滚。
- 360px 或 VS Code 支持的最小 Editor 宽度截图与溢出检查。
- 至少浅色、深色和高对比度主题各一次视觉检查。
