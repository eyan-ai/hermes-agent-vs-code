# Hermes Agent 正文文档链接设计

## 目标

让 Agent 最终回答正文中明确表示本地文档的路径可以点击，并在 Hermes Agent 专属 Editor 区之外的文档 Editor 区打开。

## 修改范围

- Markdown 行内代码和裸文本中的文档路径识别。
- Webview 到扩展端的独立 `openGeneratedDocument` 消息。
- 扩展端对绝对路径、工作区相对路径和以 `/` 开头的工作区相对路径进行存在性解析。
- 文档链接的悬停下划线和键盘可访问性沿用 `<a>` 元素行为。

## 不修改

- 输入框附件和已发送消息附件的单行横向滚动。
- 用户消息的展开与收起。
- 会话区域的窄窗口自适应。
- Read action、外部 URL 和现有附件的打开链路。
- Agent 工作列与文档工作列的隔离规则。

## 识别规则

- 行内代码内容在去除首尾空格后，以文件扩展名结尾时识别为文档路径；支持中文、空格和相对路径。
- 裸文本继续只识别无空格的路径，避免无法可靠判断普通句子中路径的结束位置。
- 普通命令、代码表达式、URL 和没有文件扩展名的内容不转换。

## 打开规则

1. `file:` URI 直接作为候选。
2. 绝对路径优先按原路径检查。
3. 相对路径依次在所有工作区根目录和当前工作目录下检查。
4. `/DataMatrix/example.md` 这类路径若系统绝对路径不存在，再按工作区根目录下的 `DataMatrix/example.md` 检查。
5. 只打开真实存在且不是目录的候选；找不到时显示明确提示。
6. 成功解析后复用 `openDocumentUri()`，继续由现有逻辑选择文档 Editor 区。

## 验收标准

- `` `/DataMatrix/Ontology场景地图.html` `` 和带空格的中文路径生成可点击链接。
- 点击发送 `openGeneratedDocument`，不复用 `openAttachment`。
- 普通 `` `npm run test` `` 不生成文档链接。
- 工作区相对路径可以解析；系统中真实存在的绝对路径不会被工作区候选覆盖。
- 现有静态、单元、契约和 Webview 视觉回归继续通过。
